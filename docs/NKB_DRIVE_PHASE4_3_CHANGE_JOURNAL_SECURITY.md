## 1. THREAT ANALYSIS: THE UNSCOPED CHANGE JOURNAL FLAW

In desktop cloud drives (e.g. Google Drive, OneDrive), real-time file updates are distributed to desktop clients via cursor-based delta streams to avoid costly full-disk re-scans. 

In the initial implementation of `server/controllers/driveController.js`, `getChanges` queried `drive_change_journal` with a global filter:
```sql
SELECT event_id, event_type, entity_type, entity_id, parent_id, name, size_bytes, sha256, performed_by, created_at
FROM drive_change_journal
WHERE event_id > $1
ORDER BY event_id ASC
LIMIT $2;
```

### 1.1 Exploit Scenario
Because this query lacked any join or condition against user departments or folder permissions:
- If an Executive uploaded `Board_Meeting_M&A_Confidential.pdf` in Department 1 (Executive),
- Or if HR created `Q4_Termination_List.xlsx` in Department 6 (Finance & HR),
- **Any regular employee** in Department 5 (Engineering) polling `GET /api/v1/drive/changes?cursor=0` immediately received the exact filenames, UUIDs, file sizes, SHA-256 hashes, timestamps, and author user IDs of those confidential documents.

This constituted a critical data exfiltration and cross-department privacy violation.

## 2. REMEDIATION ARCHITECTURE & SCOPED QUERY DESIGN

Pursuant to the **Existing NKB Cloud Permission Rules**, change journal events must strictly reflect what the authenticated employee is authorized to see in the web application.

### 2.1 Access Control Invariants
1. **Administrative Tier (`SUPER ADMIN` / `ADMIN`):** Unrestricted visibility across all change journal events for system health, backup, and global synchronization.
2. **Standard User Tier (`STANDARD USER` / `VIEWER`):** A change journal event is returned **if and only if** at least one of the following criteria is met:
   - **Own Operations:** `performed_by == req.user.id` (events generated by the user's own actions).
   - **Department Folders:** The parent folder or entity folder belongs to the user's department (`department_id == req.user.department_id`) or is owned by the user.
   - **Department Files:** The entity file is in a folder belonging to the user's department, or owned by the user.
   - **Explicit File Shares:** The file is explicitly shared with the user (`shared_with_user_id == req.user.id`) or with the user's department (`shared_with_department_id == req.user.department_id`) via an active, unexpired record in `file_shares`.
   - **Explicit Folder Shares:** The folder is explicitly shared with the user or their department via `file_shares`.

## 3. IMPLEMENTED SECURE SQL ENGINE

The scoped query uses indexed subqueries that leverage existing PostgreSQL indexes on `folders`, `files`, and `file_shares`:

```javascript
export async function getChanges(req, res) {
  try {
    const cursor = parseInt(req.query.cursor || '0', 10);
    const limit = Math.min(parseInt(req.query.limit || '50', 10), 200);
    const userId = req.user.id;
    const userRole = req.user.role_name || req.user.role || 'STANDARD USER';
    const deptId = req.user.department_id;
    const isAdmin = (userRole === 'SUPER ADMIN' || userRole === 'ADMIN');

    let query;
    let params;

    if (isAdmin) {
      // Unrestricted system stream for administrators
      query = `
        SELECT event_id, event_type, entity_type, entity_id, parent_id, name, size_bytes, sha256, performed_by, created_at
        FROM drive_change_journal
        WHERE event_id > $1
        ORDER BY event_id ASC
        LIMIT $2;
      `;
      params = [cursor, limit];
    } else {
      // Scoped change query: strictly enforce department and folder authorization
      query = `
        SELECT j.event_id, j.event_type, j.entity_type, j.entity_id, j.parent_id, j.name, j.size_bytes, j.sha256, j.performed_by, j.created_at
        FROM drive_change_journal j
        WHERE j.event_id > $1
          AND (
            j.performed_by = $3
            OR j.parent_id IN (
              SELECT f.id FROM folders f 
              WHERE f.is_trashed = FALSE AND (f.department_id = $4 OR f.owner_id = $3)
            )
            OR j.entity_id IN (
              SELECT f.id FROM folders f 
              WHERE f.is_trashed = FALSE AND (f.department_id = $4 OR f.owner_id = $3)
            )
            OR j.entity_id IN (
              SELECT fil.id FROM files fil
              WHERE fil.is_trashed = FALSE AND (fil.owner_id = $3 OR fil.folder_id IN (
                SELECT f.id FROM folders f WHERE f.is_trashed = FALSE AND (f.department_id = $4 OR f.owner_id = $3)
              ))
            )
            OR j.entity_id IN (
              SELECT s.file_id FROM file_shares s
              WHERE s.is_revoked = FALSE AND (s.expires_at IS NULL OR s.expires_at > CURRENT_TIMESTAMP)
                AND (s.shared_with_user_id = $3 OR s.shared_with_department_id = $4)
            )
            OR j.parent_id IN (
              SELECT s.folder_id FROM file_shares s
              WHERE s.is_revoked = FALSE AND (s.expires_at IS NULL OR s.expires_at > CURRENT_TIMESTAMP)
                AND (s.shared_with_user_id = $3 OR s.shared_with_department_id = $4)
            )
          )
        ORDER BY j.event_id ASC
        LIMIT $2;
      `;
      params = [cursor, limit, userId, deptId];
    }

    const result = await db.query(query, params);
    const changes = result.rows;
```

## 4. SECURITY AUDIT & VERIFICATION EVIDENCE

### 4.1 Cross-Department Isolation Test (Test 05)
- **Setup:** Admin user created folder `"Confidential IT Infrastructure"` (Folder ID `c30dce45-0bcc-45c3-bba8-8b1c80ba2ab9`) in Department 2 (IT & Systems Infrastructure).
- **Attack Simulation:** Standard user in Department 5 (Engineering & Design) requested change journal from `cursor = 0`.
- **Observed Result:** 
  - Admin stream contained the folder creation event `FOLDER_CREATED`.
  - Engineer stream returned **0 events** associated with `c30dce45-0bcc-45c3-bba8-8b1c80ba2ab9`.
  - `leakedFolder === undefined` (**PASS**).

### 4.2 Revoked Device Access Test (Test 04)
- **Setup:** Workstation device enrolled and subsequently revoked via `/api/v1/drive/devices/:id/revoke`.
- **Attack Simulation:** Revoked device attempted to poll change journal with `x-device-id`.
- **Observed Result:** HTTP 403 Forbidden with `{"code":"DEVICE_REVOKED"}` (**PASS**). Zero change events delivered.

### 4.3 Missing Identity Test (Test 02)
- **Setup:** Request submitted with valid JWT Bearer token but without `x-device-id`.
- **Observed Result:** HTTP 401 Unauthorized with `{"code":"MISSING_DEVICE_ID"}` (**PASS**).
